The uncommitted implementation adds SOP-3 through SOP-6 evaluation, the ETE lower-bound result, article aggregation, evidence construction, and DecisionCore hashing. SOP-3 and SOP-6 preserve an `insufficient_data` outcome unless a known reading independently proves their OR or any-station threshold. SOP-4 limits its historical peak to readings at or before the selected current snapshot, and ETE represents unavailable saturation as an explicit lower-bound variant rather than a calculated zero. **Watch for: confirmed high severity: `buildDecisionCore` returns mutable aliases of the input decision facts, so the returned `core_hash` can cease to represent the DecisionCore that is persisted.**

## High-level view

The decision builder sets `immutable_after_commit` to `true`, but it neither copies nor freezes nested facts. Callers can mutate their original arrays or nested objects after assembly, which mutates the returned core without recalculating its hash. This defeats the core's immutable decision-record contract at the handoff to persistence.

## DecisionCore facts remain mutable after assembly

**confirmed, high severity.** `buildDecisionCore` creates only a shallow object with `{ ...input }`, then calls `calculateCoreHash` on that object and returns the same nested references. `readonly` provides no runtime protection. A caller that retains `input.triggered_articles`, `input.evidence`, `input.policy`, or a route-candidate object can change it after `buildDecisionCore` returns. The DecisionCore then contains new decision facts while retaining the hash of the earlier facts.

```ts
const triggeredArticles = [1, 2];
const core = buildDecisionCore({ ...input, triggered_articles: triggeredArticles });
triggeredArticles.push(6);
// core.triggered_articles now includes 6, but core.core_hash is unchanged.
```

This applies before persistence as well as after a caller passes the object to a persistence layer. The current test only verifies that an untyped `immutable_after_commit: false` is overwritten; it does not verify object immutability or input-alias isolation. Clone and deep-freeze the value before calculating the hash, and test both mutation of the original input and mutation of the returned core.
